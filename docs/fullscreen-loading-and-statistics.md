# 全屏加载与体验统计

在线 Marketplace 版本由主插件和完整全屏运行包组成。主插件继续负责播放器、歌词来源、后两首预取、侧栏和普通歌词页。启动和更新检查不会下载全屏包、读取全屏缓存或初始化全屏 React 组件。只有打开全屏或影院入口才加载完整运行包；本版不按视觉模式进一步拆分。

首次加载保留 Spotify，显示可取消的提示。成功后打开影院视图，来自底部全屏入口时尝试原生全屏；较长下载可能使用户激活失效，此时仍能使用影院视图和现有全屏按钮。下载失败保留重试和关闭。导航离开、关闭及无歌曲会取消等待；切到另一首歌后挂载最新歌曲，迟到结果不会挂载已关闭的视图。

全屏包经 Worker 和国内镜像竞速获取，失败时尝试 jsDelivr。下载和本地 Cache API 读取均验证完整 SHA-256 后再执行。成功的模块在会话中复用，缓存跨重启保留，最多保留三个运行包。缓存损坏会删除并重新下载；存储受限或额度不足仍可联网加载。关闭全屏会清理画布、监听和场景，已经导入的代码仍可留在浏览器模块缓存中。

`deno task offline` 继续生成内嵌全屏的单文件，运行包无需联网下载。歌词和字体的原有联网行为不变。

## 版本与发布

`latest.json` 保留 `schema: 1`、`version`、`file` 和 `sha256`，增加 `fullscreen: { api: 1, file, sha256 }`。主包嵌入同一全屏描述符；运行时不会另查最新指针，不会将运行中的旧主包与新全屏混用。旧加载器忽略可选字段并仍能载入新主包。

全屏文件名为 `beautiful-lyrics-reborn-fullscreen.<SHA-256前16位>.mjs`。发布验证检查主包及全屏的 MIME、不可变缓存头和完整哈希。清理脚本保留当前及前两个主包，以及这些主包对应的全部全屏包。相同全屏内容复用同一个文件。回滚同时恢复主包指针及对应的全屏资源；不要仅保留当前全屏包。

上线顺序：先以现有部署流程发布支持全屏资产及 `/metrics` 的 Worker，再发布新主插件。现有 CI 把 Worker 与两个资产同批发布并验证。部署前确认 Analytics Engine dataset `lyrics_metrics` 和限流绑定可创建；`STATS_ACCOUNT_ID`、`STATS_API_TOKEN` 沿用现有统计查询配置，令牌应有 Analytics Engine 查询权限。限流 namespace `823601` 为本服务保留，其他 Worker 不应复用。不需要 D1 数据库迁移。未配置统计查询凭据时页面显示统计不可用；不影响歌词功能。

## 统计口径

现有 `lyrics_outcomes` 数据集继续保存旧的逐字、逐行、纯文本及未命中计数。新增 `lyrics_metrics` 分开记录服务端与插件事件，不从 D1 日志扫描聚合。

- 服务端：每次有效歌词 API 请求的结果和总耗时，包含预取；每个非元数据来源尝试的来源、直连/代理、阶段、结果、耗时、重试次数与是否最终采用。取消与屏蔽单列，不进入来源成功率分母。一个来源返回可用歌词不意味着被采用，最终选择只标记一次。
- 插件：每会话一次启动、一次成功首次使用全屏；前台歌词可用耗时、视图首次显示等待、全屏加载来源/耗时/结果及全屏模式使用。后台预取本身不写插件等待事件，取消或过期加载不写完成事件。
- 缓存：`cache` 为持久歌词缓存，包含预取已完成并存储的结果；`prefetch` 为前台复用进行中的预取；`network` 为直接网络获取。缓存复用率按前台加载的 cache + prefetch / 全部前台加载计算。
- 首次显示：在可见歌词视图开始等待，至歌词挂载后的绘制机会结束；隐藏、关闭、切歌的等待排除。同一次前台加载在卡片/普通页/全屏重复渲染只记一次。隐藏后再次可见重新计时，不把后台停留算入等待。
- 全屏使用比例：首次使用事件数 / 启动事件数，是统计窗口内会话事件的估算。跨窗口会话和上报丢失可能使比例偏离实际，不能当作独立用户比例。模式使用次数是打开或切换到该模式的次数。

`POST /metrics` 仅接受 `schema: 1` 与 1–20 个固定字段事件，请求体不超过 16 KiB；独立限流每 Cloudflare 地点每 IP 120 请求/分钟，属于近似限流。成功返回 204；无数据集返回 503，超限返回 429。客户端每 30 秒或累计 20 条发送，最多暂存 100 条，发送超时/失败丢弃、不重试、不落盘，离开页面尝试发送。请求不附带凭据。

插件统计统一开启，不提供开关。上报字段只有事件类别、版本、耗时、缓存来源、结果、歌词类型、视图及模式；不会附带歌曲/歌手/歌词、账号、Spotify Token 或长期用户标识。服务端限流仅临时使用连接 IP，不写入统计数据；基础设施的访问日志独立于统计事件。

`GET /stats?days=7|30|90` 保留旧字段，追加 `metrics` 分区：`server`、`providers`、`providerLatency`、`client`、`trend`、`latency`。每个分区包含固定维度的聚合行，计数为加权估计；平均值及 P50/P95 按 `_sample_interval` 加权。来源总耗时分位数单独查询，不能平均多个分组的 P95。新数据缺失显示“暂无数据”，查询失败不影响旧命中率。页面防止快速切换范围后旧响应覆盖新范围。Analytics Engine 保留三个月，插件事件可能因网络丢失而不完整。

## 验证

扩展 Node 测试验证惰性加载、哈希、缓存损坏、镜像回退、取消、重复调用、挂载失败恢复、预取口径和显示事件去重。Folia Playwright 覆盖所有 13 模式、播放/暂停/拖动/缩放/清理、统计页面窄屏及请求竞态；测试运行包为真实编译产物。Worker 测试验证固定事件字段、流式体限制、限流、选中来源与采样 SQL。最终还需在安装了 Spotify 和 Spicetify 的机器完成在线初次打开、重启缓存复用及离线包安装验收。
